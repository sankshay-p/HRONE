# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Hardcoded `{"status": "ok"}` without pinging MongoDB; returns 200 even when database is down instead of 503 per OpenAPI contract. | Stop MongoDB or provide invalid `MONGO_URI`; `GET /health` returns 200 instead of 503. | Added `client.admin.command("ping")` within try/except block; raises HTTP 503 on connection failure. |
| 2 | Startup / Lifespan (missing in starter) | No indexes are created on startup. Lacks unique constraints on `employees.emp_code` and `attendance_logs.(emp_code, date)`, and causes full collection scans (`COLLSCAN`). | Inspect indexes with `getIndexes()` or run `GET /admin/explain/attendance_list`; plan contains `COLLSCAN` and duplicate records can be inserted. | Added a FastAPI `lifespan` handler creating all unique and query indexes idempotently at startup. |
| 3 | `compute_late_minutes` (lines 33-37) | Grace period logic bug (R2): `minutes > 10` checks floored minutes. At 10m 01s (601s), `601 // 60 = 10`, `10 > 10` is False, returning 0 instead of 10. | Punch-in at 09:40:01 for a 09:30 shift returns 0 late minutes instead of 10. | Changed condition to check elapsed seconds strictly exceeding grace period (`elapsed_sec > 600`), then return floored minutes (`int(elapsed_sec // 60)`). |
| 4 | `compute_late_minutes` (lines 33-37) | Timezone and shift date mismatch: `punch_in.replace(hour=h, minute=m)` replaces hours on UTC/naive datetime instead of IST, and ignores overnight shift dates. | With UTC datetime (04:10 UTC = 09:40 IST), replacing with 09:40 UTC produces a 5.5 hour discrepancy. | Converted instant to IST, constructed shift start datetime in IST on the record's attendance date, and truncated instants to whole seconds (R1). |
| 5 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round()`, which applies Banker's rounding (round half to even) instead of half-up rounding (R4). | Duration of 2.525 hours gives 2.52 with `round()` instead of 2.53 under half-up. | Converted duration seconds to `Decimal` and quantized using `ROUND_HALF_UP`. |
| 6 | `compute_overtime` (lines 44-47) | Returns overtime for less than 30 minutes, violating R3 (which mandates >= 30 min minimum, otherwise 0). | Punch-out 15 minutes after shift end returns 15 overtime minutes instead of 0. | Added check: returns `int(ot_sec // 60)` only when `ot_sec >= 1800` (30 minutes), otherwise returns 0. |
| 7 | `compute_overtime` (lines 44-47) | Overnight shifts end on the next calendar day (`date + 1 day`), but starter constructs shift end using `date_str` directly. Also risks naive/aware datetime subtraction TypeError. | Overnight shift 22:00-06:00 on 2026-07-06 with punch-out at 06:40 on 2026-07-07 computes overtime against 2026-07-06 06:00 (24h past), giving ~1480 min overtime instead of 40. | Detected overnight shift (`shift_end <= shift_start`) and added 1 calendar day to shift end instant in IST. |
| 8 | `EmployeeIn` model & `create_employee` (lines 53-61, 77-86) | Missing schema validations: `emp_code` regex (`^EMP\d{4,6}$`), email regex, name/department length limits, date format for `joined_on`, and shift inequality check. | `POST /employees` with `shift_start: "09:30", shift_end: "09:30"` or invalid email succeeds with 201 instead of 422. | Added Field constraints, regex validators, and model validator ensuring `shift_start != shift_end`. |
| 9 | `create_employee` (lines 79-85) | Check-then-insert race condition: `find_one` followed by `insert_one`. Concurrent requests with the same `emp_code` both insert or raise unhandled 500 error. | Parallel `POST /employees` requests with identical `emp_code` result in duplicate records or unhandled 500. | Backed `emp_code` with a unique index, caught `DuplicateKeyError`, and returned HTTP 409. |
| 10 | `create_employee` (lines 82, 85) | Returns `created_at` as ISO string or local naive datetime instead of epoch milliseconds (`EpochMillis` integer). | `POST /employees` response contains string `"created_at": "2026-07-06T10:30:00"` instead of integer epoch milliseconds. | Stored UTC BSON datetime in MongoDB and converted `created_at` to integer epoch milliseconds in API response. |
| 11 | `list_employees` (lines 93, 95) | Pagination offset off-by-one error: `skip = page * page_size` skips items 1-20 for page 1. | `GET /employees?page=1&page_size=2` returns items #3 and #4 instead of #1 and #2. | Changed calculation to `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (line 94) | `total` count ignores filter: `db.employees.count_documents({})` counts whole collection, violating R10. | `GET /employees?department=Engineering` returns total count of all company employees rather than Engineering employees. | Passed filter `q` into `count_documents(q)`. |
| 13 | `list_employees` (line 95) | Missing sorting: OpenAPI specifies items must be sorted by `emp_code` ascending. | `GET /employees` returns documents in non-deterministic storage insertion order. | Added `.sort([("emp_code", ASCENDING)])` to query. |
| 14 | `punch_in` (lines 101, 113) | Crash with 500 when employee is not found: `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable`. | `POST /attendance/punch-in` with `emp_code: "EMP9999"` returns 500 Internal Server Error instead of 404. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 15 | `punch_in` (lines 104-118) | Check-then-insert race condition on punch-in. Parallel punch-ins for same employee and date both insert. | Parallel punch-in requests create duplicate logs, violating contract ("exactly one gets 201 and rest 409"). | Backed by compound unique index `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 16 | `punch_in` (lines 102-103) | Wrong attendance date (R1): `d = ts.date().isoformat()` uses UTC/local date instead of IST, and does not handle overnight shifts where early morning punch belongs to previous day. | Overnight shift 22:00-06:00 punched in at 05:30 IST on July 7 gets assigned date `2026-07-07` instead of `2026-07-06`. | Converted to IST, checked if `shift_end <= shift_start` and IST time < `shift_end`; if so, subtracted 1 day per R1. |
| 17 | `punch_in` (line 119) | Injects `"id"` field into response (`doc["id"] = str(res.inserted_id)`). OpenAPI schema specifies no `id` or `_id`. | Validating response against `AttendanceRecord` fails schema validation due to unexpected `id` property. | Removed `doc["id"] = ...` and excluded `_id` and `id` from response. |
| 18 | `punch_in` (line 110) | `punch_in` serialized as ISO datetime string instead of integer epoch milliseconds. | Client receives ISO string `"2026-07-06T03:58:00"` instead of epoch ms integer like `1783310280000`. | Converted BSON datetimes to epoch milliseconds at the API boundary. |
| 19 | `punch_in` (line 66) | `PunchInIn` allows arbitrary status strings (e.g. `ABSENT`, `LEAVE`) instead of `PresenceStatus` enum. | `POST /attendance/punch-in` with `status: "LEAVE"` succeeds with 201 instead of 422. | Restricted `status` in request model to `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 20 | `list_attendance` (lines 144-147) | Loads entire collection into Python memory (`list(db.attendance_logs.find(q))`) and sorts in Python. Fails on 100k docs. | Memory exhaustion, high latency, and COLLSCAN on large collections. | Used database-level `.sort([("date", DESCENDING), ("emp_code", ASCENDING)])`, `.skip()`, and `.limit()`. |
| 21 | `list_attendance` (line 145) | Missing secondary sort by `emp_code` ascending; only sorts by `date` descending. | Ties on `date` have non-deterministic ordering across requests. | Added compound database sort: `[("date", -1), ("emp_code", 1)]`. |
| 22 | `list_attendance` (lines 127-128) | Missing validation for `date_from > date_to`: returns 200 with empty list instead of 422. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 instead of 422. | Added validation raising HTTP 422 when `date_from > date_to`. |
| 23 | `list_attendance` (lines 148-150) | Injects `"id"` and fails to serialize timestamps to epoch milliseconds. | Response items contain `"id"` and unformatted datetime objects. | Excluded internal `_id` and converted all datetimes to epoch milliseconds. |
| 24 | `list_attendance` (data mapping) | Missing legacy document field defaults: sample document 9 omits `history` and `half_day`. | Reading legacy documents returns missing fields or raises KeyError. | Provided explicit defaults (`history: []`, `half_day: False`, `late_minutes: 0`, `overtime_minutes: 0`). |

Also note anything you looked at and decided was **not** a defect, and why:
- `load_dotenv()`: We examined whether `load_dotenv()` would overwrite existing environment variables. By default in `python-dotenv`, `load_dotenv(override=False)` preserves existing environment variables, ensuring real environment variables injected by the grader (`MONGO_URI`, `MONGO_DB`) take precedence.
- String format for `date` (`YYYY-MM-DD`) and shift times (`HH:MM`): The use of plain strings for calendar dates and shift times matches DATA_MODEL.md section 1 intentionally, avoiding spurious timezone offsets.
